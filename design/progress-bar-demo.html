Progress bar — every property

The SLDS Progress Bar blueprint rendered in our own markup, with the ARIA the blueprint prescribes. Everything is inside a table cell, because that is the only place it will ever appear and a bar behaves differently when its width comes from a column.

Theme: The fills are var(--slds-g-color-…, #hex). SLDS 1 has no hooks so the hex shows; switching defines them and the var wins.

Theme — the conditional-formatting palette

Same vocabulary as a rule's Style, so "Success" means the same green in a gauge as in a colored cell. All at 65%, medium thickness, value shown.

Thickness — the blueprint's size scale

A bar's width is the column's, so height is the only dimension left. Check the bold value stays readable at x-small: that is the case the layout has to survive.

Ends, and the value

Values — scaling and clamping

A Salesforce Percent field stores 25 for 25%, which is already what a gauge wants — no fraction conversion. "Value at 100%" rescales anything else. Out-of-range values clamp rather than overflowing the track.

In context

Beside ordinary columns, with a row hovered in the browser so you can see the bar is unaffected by the hover repaint — it is our own markup, not a cell background.
