Column attributes — treatment C, developed

The rule that makes two editing surfaces workable: if you would want to compare it across columns, it is in the grid row. If it only makes sense for one column, it is in the drawer. That puts order, label, width, alignment and the four flags in the grid — scannable and comparable — and puts type, everything the type implies, conditional formatting and the raw escape hatches in the drawer.

The grid

Everything here is comparable down a column, which is the test for belonging. The Rules pill is a read-only count: it tells you a column is formatted without pretending rules can be edited in a table cell.

Decisions this makes, and what is still open

Made here. The grid keeps the comparable attributes and gains a Sort flag and a read-only rule count. Scale is replaced by Minimum and Maximum decimals, which are the datatable's own minimumFractionDigits/maximumFractionDigits — Scale was our invention on top of them, and existing configs will need migrating. Conditional formatting lives in the column drawer, with the grid showing only a count. The rule editor gains an Emphasis control, which is the one idea worth taking from Avonni's class list.

Added 2026-09-26, from Chris. The Type list is filtered by the field's DisplayType, so a Date/Time field never offers Currency or Checkbox; with no describe, as for a user-defined object, everything is offered because nothing can be ruled out. Currency code is detected rather than assumed — UserInfo.isMultiCurrencyOrganization() was measured working, and in a multi-currency org the list comes from the ACTIVE rows of CurrencyType, read with dynamic SOQL because the object does not exist at all in a single-currency org and static SOQL would not compile. The header icon moves into Advanced behind an icon picker. And colour becomes one choice of three — None, Per column, or Conditional — with Per column and Conditional mutually exclusive, because a column-wide colour fighting a per-cell rule over the same cell has no sensible answer.

Still open. Whether the drawer is inline, as drawn, or a right-hand panel — inline keeps context but pushes rows down once a couple of rules exist. Whether the Type picklist should ever offer a type the field cannot support, or only sensible re-displays. And whether an Icon field belongs in the rule, or whether icons deserve their own row-level treatment.
